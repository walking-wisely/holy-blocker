radix domain/IP filter done; SNI parser done; tun adapter + PacketSink dispatch done; NetShield struct + run loop done (Windows Wintun path); smoke-test done — all 5 plan steps complete. **DNS path added for the Android VPN** — `dns.rs` (RFC 1035 question parse + NXDOMAIN synthesis; compression pointers in a QNAME are rejected, never followed), `udp.rs` (IPv4/UDP framing with RFC 1071 checksums; fragments refused), `dns_shield.rs` (`DnsShield::inspect` — one pure `Ignore`/`Blocked`/`Forward` decision per packet). 70 tests. Note the deliberate asymmetry with `NetShield`: `PacketSink::pass_packet` assumes Wintun-style re-injection, which **Android does not offer**, so the DNS path returns bytes for the caller to write instead of dispatching through a sink. **Module 6 of the domain-blocklist plan (the signed-artifact loading path) is done** — `blocklist.rs`'s `BlocklistArtifact` (an `fst::Map<Mmap>` that owns its mapping, avoiding a self-referential `Arc<Mmap>`/`Map` pair while staying `Send + Sync`), `load()` (two-slot `current/`→`previous/` cold-start fallback, signature verified before `fst_digest`, fails closed on both), and `lookup()` (scope-aware, label-boundary exact-`get` matching — never prefix streaming, so `examplezzz.com` cannot match an `example.com` apex). `DnsShield` now resolves the plan's five-level precedence table (device-local `Allowlist` → explicit `DomainFilter` rules → FST → default; overlay/module 8 is unbuilt) via `resolve_action`, normalizing every query with the *same* `domain_normalize::normalize` the build side uses. `DomainFilter` gained `rule_for()` so the resolver can distinguish "no explicit rule" from "an explicit rule whose action happens to be `Proxy`" — `lookup()` alone can't tell the two apart, and `lookup` is now a one-line wrapper over it with no behavior change for existing callers. `BlocklistLookup` is the bounded-latency worker: one thread owns the artifact, answers over a channel keyed by the normalized domain, waits at most a caller-set budget (plan's starting value 2 ms) before falling back to a small LRU then the default while counting the event, and deduplicates in-flight lookups so a burst to one domain costs one worker round trip. **An adversarial review round found and fixed two real concurrency bugs**: the worker had no `catch_unwind` around the FST lookup, so a panic there would kill the whole thread (silently disabling FST enforcement for every uncached domain) and permanently strand that domain's in-flight waiters — fixed with `catch_unwind` (a caught panic answers "no rule" and the worker keeps running) plus a `panic_count()` metric; and the cache was populated after draining `inflight` rather than before, opening a window for a duplicate worker request — fixed by reordering. **Two explicit narrowings, recorded in `docs/engineering/coverage.md`:** the FST is wired into the DNS path only — `NetShield::process_packet` (the Windows/Wintun SNI path) still consults `DomainFilter` alone, the plan's own module-6 budget section is written entirely in terms of `DnsShield`, so this is scope as specified, not an oversight, and is now called out in `process_packet`'s own doc comment; and `load()` has only ever loaded the two-slot layout a test helper wrote — module 7 `cli` is now done (see the `packages/domain-blocklist` row below) and produces a real artifact in the same on-disk layout by construction, but that producer's actual output has not yet been fed through this crate's `load()` in one run, so the on-disk contract is defined and tested against but the producer and consumer have not yet met. 92 tests
