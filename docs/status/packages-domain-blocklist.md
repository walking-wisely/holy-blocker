**Module 2 of the domain-blocklist plan (`merge.rs`) done.** `types.rs` defines `SourceId` (`StevenBlack`/`Hagezi`/`Ut1`), `Category` (`Adult`/`Gambling`/`Dating`), `ScopeHint`, `RawEntry` and `MergedEntry` ahead of `sources` (module 1, unbuilt), since `merge.rs` needs somewhere to import them from. `resolve_scope()` combines `domain_normalize::classify_scope` with the parser's `ScopeHint`: `classify_scope == None` refuses the entry regardless of hint, and only a wildcard (`ScopeHint::Apex`) whose base is itself eTLD+1 ever produces `RuleScope::Apex` — a **plain** entry that happens to literally be a registrable domain is still scoped `ExactHost`, filling a gap the plan leaves implicit by mirroring the `www.`-stripping section's logic (widening without an explicit wildcard would silently over-block). `merge()` dedupes by normalized domain into a `BTreeMap`, unions `sources`/`categories` (never overwrites), takes the wider scope on a collision, and carries three drop counters (`MergeReport`: normalization failure, public-suffix/denylist, IP literal) so a parser regression and a PSL surprise never look like the same event. `filter_by_category()` is a pure any-of filter; `flag_personal_name()` matches the plan's own named cases (`red-panda` flagged, `janedoe` missed) and rejects `xn--`-prefixed (punycode) labels, which would otherwise false-positive across the whole IDN corpus. **An adversarial Opus review** found and fixed four real gaps — denylist entries are now normalized once in `merge()` before use (a hand-typed denylist with a stray case/trailing-dot mismatch previously failed to match, silently); IP literals are dropped and counted rather than passed through as domain rules; `sources`/`categories` are sorted for input-order-independent, reproducible output; `flag_personal_name`'s punycode false-positive above — and one claim (that a plain eTLD+1 entry should get `Apex` without a wildcard) was investigated and rejected against the plan's own "merging two entries with different scopes takes the wider scope" text. 36 tests. **Module 5 (`gates.rs`), built third per the plan's implementation order, is done — including a second adversarial (Opus) review's fixes**, `shrinkage_gate`/`growth_gate`/`false_positive_gate`/`size_gate`/`license_gate`, each a pure `GateResult::Pass`/`Fail(String)` decision naming the evidence (which control domains hit and under which sources, which license and source, the measured percentage against the limit, capped at 20 named hits) rather than a bare boolean. `shrinkage_gate`/`growth_gate` take `PreviousBuild<T>` (`None`/`Existing`), not a bare zero/`Option` — the review found a manifest-load failure and a genuine first build both looked identical as `0`/empty, silently disabling both gates' percentage checks on the easiest mistake to make; every threshold-taking gate now also validates it's finite and in `[0, 1]` first, since a `NaN` threshold previously made every `>` comparison silently `false` and passed the gate unconditionally. `false_positive_gate` is a substantially redesigned mechanism, not just a fix: Tranco carries no content-category metadata and genuinely contains adult sites at ~1–2.5% density (not "a handful"), so the plan's original "subtract a hand-maintained exclusion file" design doesn't scale to manual review — replaced by **cross-source corroboration** (`FalsePositiveHit::is_corroborated()`: two or more independently-maintained sources agreeing outweighs one source's own file-level curation mistake) plus `review_queue()` narrowing manual triage to only the uncorroborated, unexcluded hits; see the decision doc's "cross-source corroboration" section, including its accepted independence-assumption limitation. Also fixed: `control_set`/`exclusions` are now normalized before comparison (an earlier version matched nothing against an unnormalized control set and reported a false 0% rate — the exact bug class `merge.rs`'s own earlier review already fixed once, reintroduced here); lookup is a `HashMap` index (O(control + merged), confirmed ~10¹² comparisons at realistic scale under the old nested-scan version); and a `min_control_size` floor fails an empty/truncated control-set fetch that previously passed silently. `license_gate` gained a `merged` parameter and now fails when a contributing source has **no** snapshot at all (an omission, the cheaper mistake a license-only check missed entirely) or when snapshots duplicate a source (ambiguous coverage), and compares licenses case/whitespace-insensitively via `LicenseId::spdx_matches`, matching SPDX's own rule. (module 7, unbuilt).** `LookupResult`/`UnknownReason` model one single-QTYPE (A or AAAA) answer behind a `DnsLookup` trait; `check()` combines one A and one AAAA lookup into a `Verdict` (`Alive`/`Dead`/`Unknown`) via the plan's three-step order — either resolving is `Alive`, both `NxDomain` is `Dead`, otherwise (at least one `Unknown`, neither `Resolved`) is `Unknown`, covering the plan's named mixed `NxDomain`/`Unknown` case explicitly rather than by accident. `due_for_check(cache_entry, now, ttl_seconds)` deliberately takes no cadence parameter — cadence is the caller's coarser scheduling concern the plan keeps decoupled from and a multiple of the TTL, and folding it in here would let a caller conflate the two — and reads clock skew (`now` before `last_checked`) as "just checked" via `saturating_sub` rather than underflowing into a bogus due-forever gap. `should_prune()` is the one-line "only `Dead` prunes" rule, tested for first-seen- vs. previously-cached-`Unknown` separately per the plan's own split. `canary_check()` runs `alive_controls` then `dead_controls` through `check()` and returns `CanaryResult::Failed { detail }` naming the misbehaving control and what was expected, distinguishing a family-filtering resolver, a wildcard-sink resolver, and an inconclusive resolver as three separately tested failures — including that an `Unknown` canary result fails the canary even though a real sweep would keep an `Unknown` domain, since the control set is supposed to be unambiguous; discarding the sweep and refusing to write the cache back on any canary failure is `cli`'s job, per the plan. **`dead_controls` is a `Vec`, symmetric with `alive_controls`, not a single `String`** — a lone dead control is one resolver quirk away from a false pass, and `canary_check` already loops so checking more than one costs nothing extra. **`liveness.rs` was then split into `liveness/{mod,lookup,cache,canary}.rs`** (pure reorganization,
