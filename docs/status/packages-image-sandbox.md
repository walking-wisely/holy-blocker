**v0 done: decode → tile → ONNX → max → verdict, wired into `mitm-proxy`.** The deployed geometry is **tile-max**, not the evaluation centre crop: `preprocess_tiles` resizes the shorter side to **224 exactly** (not `224*1.14` — no crop follows), slides 224 windows along the longer axis at a half-window stride with the last flush to the far edge, and `sandbox.rs` takes the **max** score over tiles. Averaging is wrong here — it dilutes a small explicit region into a large safe background, the exact failure being fixed. A near-square image yields **one** tile, so ordinary imagery costs one inference; the 8:1 aspect clamp now bounds *inference count* (worst case 15) rather than allocation. **Both v0 constants were guesses and both were wrong**, now measured (see the `machine-learning` row): threshold 0.20 → **0.4650**, floor 32px → **96px**. A threshold belongs to a model **and** a geometry — the same checkpoint under a centre crop operates at 0.2717, and reusing it under tile-max over-blocks 14.73% against 10.09% with nothing failing to indicate it. `preprocess` (centre crop) is **kept**, because every published figure was measured under it and `tests/parity.rs` pins it against torchvision — that fixture caught a real off-by-one (torchvision's `CenterCrop` rounds the half-pixel offset up; truncating shifted the crop 1px and moved the tensor mean by 0.0085). `tests/tile_parity.rs` does the same for the tiled path against `inputs.tile_geometry`, using a fixture whose green channel ramps left-to-right so tile **position** shows up in each tile's mean — matched torchvision on the first run. `classifier.rs` pins the score contract from `labels.py`/`eval.py` (`softmax(logits)[1]`, block at `>=`) behind a non-default `onnx` feature; `sandbox.rs` fails open on every path — undecodable bytes, size floor, aspect clamp, missing model, inference error — and abandons the whole image if any *one* tile fails, since a max over a subset scores a different image. 50 tests. pHash + SQLite **not built** — no hash database exists or can be populated in-repo, so it is a cache in front of the model rather than a prerequisite. A fully convolutional equivalent (MobileNetV3's pool+linear head → 1×1 convs, one pass whose spatial max equals the tiled max, plus a heatmap for the screen path) is the noted follow-up if 15 passes ever costs too much
