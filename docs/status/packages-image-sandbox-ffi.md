# `packages/image-sandbox-ffi` — status

Language: Rust

UniFFI wrapper over image-sandbox's raw-frame path — `ImageGuard` + `withModel`/`disabled`/`classifyFrame`/`threshold`, `ImageOutcome` as an enum-with-fields so the Swift binding is an enum with associated values. **Construction is fallible, classification is not**: a missing model must be loud (a daemon reporting image scanning as on while classifying nothing is the failure the fallible constructor exists to prevent), while `image-sandbox` already fails open internally and making every caller reimplement that rule is how such a rule gets got wrong. `ImageOutcome.Allow` carries an **optional** score for the same reason `ScoredVerdict` does. Deliberately exposes only the raw-frame path, never `check` — an encoded-bytes entry point would invite a caller to PNG-encode a captured frame just to have it decoded again. `Vec<u8>` crosses as Swift `Data` **by copy** (~5.9 MB per call at Retina size, on a ~500 ms cadence), accepted rather than designed around: zero-copy would mean a raw pointer with a lifetime Swift cannot express. Built by `native-modules/mac-daemon/scripts/build-ffi.sh`, which now loops over both FFI crates. **This is the ONNX half of the runtime split — `apps/mobile` must not be wired to it**. `ImageOutcome` gained a `Warn { score: f32 }` case for the `sexy` tier (`Allow`'s score stays optional; `Warn`'s never is, since it is only ever produced after a real classification), and `ImageGuard.withModel` now takes `sexyThreshold`/`explicitThreshold` instead of one `threshold` — both required, same no-built-in-default rule as before. A new `sexyThreshold()` getter sits beside the existing `threshold()`
